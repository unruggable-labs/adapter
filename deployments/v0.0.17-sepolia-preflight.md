## Storage and rehearsal

Current regular storage is slot 0 (`__deadRegistrySlot`, reserved) and slot 1
(`_bindings`). The packed binding remains `(uint8 standard,address boundAddress,uint256 tokenId)`.
Existing values 0–2 retain their meaning. No initializer, reinitializer or migration
is called. OZ ownership and initialization preservation are exercised on the live fork.

`test/Adapter8004.sepolia-fork.t.sol` checks:

- The expected live implementation, Safe owner and registry before upgrading.
- Three real existing bindings (agent IDs 9122–9124), including registry ownership,
  URI, binding metadata and wallet, unchanged after the upgrade.
- A binding registered through the actual outgoing implementation before upgrading.
- A real delegate-registry grant, controller checks before and after upgrading, and
  a delegated URI update through the live identity registry.
- Owner-only upgrade authorization, registry and slot-0 preservation, UUPS UUID,
  and rejection of reinitialization.
- New ACCOUNT registration, registry wallet cleanup, binding hash agreement and
  caller-only wallet UBID set/clear calls after upgrading.

Only the test NFT is mocked. The proxy, Safe, identity registry and delegate registry
are actual forked contracts. All test writes are local. Two current owners approve the
transaction hash on the fork, and the real Safe executes the upgrade through its
2-of-4 threshold and nonce logic. Approved-hash signatures avoid owner private keys;
the rehearsal therefore validates Safe execution but not cryptographic signature
collection or the Safe web application's transaction construction.

## Registry policy — important correction to older instructions

The registry address does not change. The constructor now receives that same address
and embeds it in implementation bytecode. `_authorizeUpgrade` checks **only ownership**;
neither the outgoing nor the proposed implementation enforces registry equality during
upgrades. This is an operator/signing check. An immutable is fixed within one
implementation, not across future owner-authorized upgrades.

## Indexer cutover

The indexer itself has not been supplied or validated. Before execution:

- Retain historical ABI decoding. `AgentBound(uint256,uint8,address,uint256,address)`
  and its indexed fields are unchanged; named `tokenContract` becomes `boundAddress`.
- Accept standards 3–7 in addition to 0–2. Address bindings (5–7) use token ID zero.
- Use current counterfactual event signatures from the compiled ABI, not old payloads.
- Replace old `registrationHash(address,uint256)` usage with current `hashBinding`
  or `bindingHashOf`. Preserve old hashes as historical keys. Current hash formula:
  `keccak256(abi.encode(adapterInteroperableAddress,standard,boundAddress,tokenId))`.
- New wallet claims are event-only: latest `WalletUBIDSet` per account wins;
  `WalletUBIDCleared` unsets. Add attestation events if indexed.
- `MetadataBatchSet` is removed; batch writes now emit individual `MetadataSet` events.
- Other removed baseline APIs include `setIdentityRegistry`, `rewriteBindingMetadata`
  and the old two-argument initializer. Do not initialize during this upgrade.
- Record the executed upgrade transaction and exact log boundary, not merely the
  implementation deployment block. Events before and after an upgrade can share a block.

## Final implementation and Safe calldata

The deployment flow keeps the two actions separate: an EOA deploys the implementation,
then the Safe executes only the proxy upgrade.

For the previous flow, the constructor argument is exactly the registry above.
`DeployAdapterImplementation.s.sol` deploys only the implementation and checks this
registry. Its dry-run output is **not deployment evidence** and must not be signed.
Explorer verification must include the ABI-encoded address constructor argument.

After implementation deployment and independent source/bytecode verification,
set `ADAPTER_IMPLEMENTATION_ADDRESS` and `EXPECTED_IMPLEMENTATION_CODEHASH` to the
verified values, then run:

```sh
forge script script/PrepareSepoliaUpgrade.s.sol:PrepareSepoliaUpgradeScript \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
```

Do not add `--broadcast` or `--resume`; the script rejects them. It checks live code,
approved runtime hash, baseline, registry, owner and UUPS UUID, then simulates the
exact call locally. The supplied expected hash must come from independently reviewed
deployment/verification evidence, not blindly from an arbitrary target address.

Output: `deployments/v0.0.17-safe-tx-sepolia-verified.json`.
Safe transaction: CALL to the existing proxy, value 0,
`upgradeToAndCall(verifiedImplementation,0x)`. No delegatecall, initializer or registry
change. The script writes no final payload until an actual implementation exists.

Before signing, verify the Safe transaction simulation, current threshold/owners,
nonce and any enabled guards/modules in the Safe UI. After execution, re-read the
implementation slot, owner, registry and sampled bindings, and record the transaction
hash and indexer cutover boundary. Do not assume a rollback to the old implementation
is safe after accepting new binding standards that it does not understand.
