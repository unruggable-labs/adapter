### Storage, authorization and test gates

`a20035c` regular storage has registry at slot 0 and `_bindings` at slot 1. v0.0.17 reserves slot 0 as `__deadRegistrySlot` and keeps `_bindings` at slot 1. Binding packing remains enum at offset 0, address at offset 1, tokenId in the following word; stored enum values 0–2 retain their meaning. Registry now comes from an implementation immutable, so the constructor must equal the old proxy's registry. Do not erase slot 0. v0.0.17 has no regular mappings at slots 2–4; older unreleased layouts must not be treated as deployed state. Compare OpenZeppelin namespaced ownership, initialization and reentrancy slots against actual historical dependencies too.

**Why `_authorizeUpgrade` is empty:** `function _authorizeUpgrade(address newImplementation) internal view override onlyOwner {}` intentionally places the entire authorization check in `onlyOwner`. It is not unrestricted. The inherited UUPS implementation handles proxy-context checks, UUID compatibility and installation through `upgradeToAndCall`. The body adds no registry-equality check: registry preservation is an operator/signing obligation, and a future authorized owner can choose a different registry implementation. This is intended in v0.0.17 and matches the Sepolia runbook.
